# 角色控制器：输入 → 意图 → 逻辑 → 表现 四层架构

## 架构总览

```
输入层            意图层             逻辑层                表现层
InputSource  ──▶  InputIntent  ──▶  CharacterMotor  ──▶  CharacterPresenter
(可替换 Node)     (纯数据 struct)    (纯 C# 类, 非Node)    (动画/朝向/特效)
   │                                     ▲
   ├─ PlayerInputSource  (读 InputMap)   │ 每帧喂入 IsOnFloor
   └─ SlimeAIInputSource (RayCast 感知)  ▼
                                  Character : CharacterBody2D (编排者)
```

每帧在 `Character._PhysicsProcess` 中按固定顺序串联（帧序确定，保证平台物理手感可复现）：

```
intent = inputSource.Poll()            // 1. 输入 → 意图
motor.Process(intent, delta)           // 2. 意图 → 逻辑（算速度、状态、事件）
Velocity = motor.Velocity; MoveAndSlide()  // 3. 物理执行
motor.NotifyFloorStateChanged(IsOnFloor)  // 4. 回喂物理状态（coyote/落地检测）
presenter.Sync(motor)                  // 5. 逻辑 → 表现
```

**玩家与敌人共用的关键**：`SlimeAIInputSource` 与 `PlayerInputSource` 产出完全相同的 `InputIntent`，逻辑层 `CharacterMotor` 不知道也不关心意图来自键盘还是 AI；差异仅在：① 换 InputSource 子节点，② 换 `CharacterConfig` 数值，③ 换外观。

## 各层设计

**意图层** `InputIntent`（readonly struct）：`MoveAxis`(-1..1)、`JumpPressed`(本帧按下)、`JumpHeld`(持续按住) —— 只描述"想做什么"。

**输入层** `InputSource`（abstract Node）：唯一方法 `InputIntent Poll()`。
- `PlayerInputSource`：包装 `Input.IsActionPressed` 等，读 `move_left/move_right/jump` 动作。
- `SlimeAIInputSource`：引用两个 RayCast2D（前方墙壁、前下方悬崖）做巡逻决策——撞墙或遇悬崖调头；config 允许时遇坑发一帧 `JumpPressed`（带冷却，空中不改轴）。无任何 Godot Input 单例依赖。

**逻辑层** `CharacterMotor`（纯 C# 类，不挂场景树，为将来单元测试留路）：
- 水平：加速/减速逼近 `MoveAxis * MaxSpeed`（离轴摩擦）。
- 跳跃手感三件套：土狼时间（离地 ~0.1s 内仍可跳）、跳跃缓冲（落地前 ~0.12s 按跳生效）、可变跳跃高度（上升中松开跳跃键削减上升速度）。
- 状态 `Idle/Run/Jump/Fall` 为推导式计算（由 IsOnFloor + velocity + intent 推出），不引入重型状态机。
- 事件 `Jumped`/`Landed`（C# event）供表现层订阅。
- 全部参数来自 `CharacterConfig : Resource`（MaxSpeed/Acceleration/Friction/JumpVelocity/CoyoteTime/JumpBufferTime/JumpCutMultiplier/GravityScale/CanJumpGaps...），玩家与史莱姆各一份 `.tres`。

**表现层** `CharacterPresenter`：读 motor 状态切换 `AnimatedSprite2D` 动画、按 Facing 翻转、订阅 Jumped/Landed 播粒子（落地尘土）。永不反向写逻辑层。

**编排者** `Character : CharacterBody2D`：持有三层引用，只做装配与调用，不含玩法规则。

## 实施步骤

1. **基础设施**：手写 `.csproj`（Godot.NET.Sdk/4.2.0，TargetFramework 按本机 dotnet SDK 定）；`project.godot` 注册 InputMap（move_left/right、jump，A/D/←/→/空格）、设主场景、像素渲染（default_texture_filter=nearest、stretch canvas_items/keep）。
2. **逻辑层先行**：InputIntent、CharacterState、CharacterConfig、CharacterMotor（含手感三件套与单元级纯函数结构）。
3. **输入层**：InputSource 抽象 + PlayerInputSource。
4. **表现层**：CharacterPresenter + 生成占位像素 PNG（python/PIL，失败则退化 PowerShell System.Drawing，再退化 Polygon2D）。
5. **Actor**：Character.cs + BaseCharacter.tscn + Player.tscn。
6. **敌人验证共用**：SlimeAIInputSource + Slime.tscn + slime_config。
7. **TestLevel.tscn**：静态地形（地面、平台、一个史莱姆跳得过/一个跳不过的坑）、Camera2D。
8. **运行验证**：用 Godot MCP `run_project` + `get_debug_output` 确认零报错；核对行为标准（见下）。
9. **收尾**：`dotnet csharpier .` 格式化（fix skill 要求）；设计文档写入 `Docs/character-controller-design.md`。

## 验收标准

- 编译零错误、运行零脚本报错。
- 玩家：加减速跑动；跳跃高度随松键变化；边缘跳落 ~0.1s 内按跳仍起跳；落地前提前按跳缓冲生效。
- 史莱姆：与玩家共用同一 `CharacterMotor`/`Character.tscn` 代码，来回巡逻、撞墙调头、遇坑（可跳的）跳过、不可跳的坑调头。
- 表现：动画随 Idle/Run/Jump/Fall 切换，朝向随移动方向翻转，落地有尘土粒子。

## 已决策的技术点

- 输入抽象用「抽象 Node + 轮询」而非信号驱动：平台物理需要严格帧序确定性，信号时序不可控。
- 状态用推导式而非显式状态机：当前能力集下更简单干净，未来加冲刺/二段跳再演进。
- 不写自动化测试（用户已选试玩验证），但 Motor 保持非 Node 纯类，为后续补测试留门。
