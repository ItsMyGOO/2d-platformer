# 战斗状态机实施计划

基于已批准的设计（Docs/combat-state-machine-design.md 待本轮写入）。现有四层架构不变，状态机属于逻辑层，共用代码原则不变（AI 与玩家产出相同意图、跑同一状态机）。

## 第 0 步：Spec 落盘
写入 `Docs/combat-state-machine-design.md`（内容即上轮已批准的设计文本）。

## 第 1 步：意图与配置扩展
- `InputIntent`：+`DashPressed`、`AttackPressed`（Create 重载同步扩展）。
- 新 `DashConfig : Resource`（Speed=420, Duration=0.18, Cooldown=0.6, EndSpeedKeepRatio=0.4）。
- 新 `AttackConfig : Resource`（WindupTime=0.12, ActiveTime=0.1, RecoveryTime=0.18, Damage=1, KnockbackHorizontal=160, KnockbackVertical=-120, Cooldown=0.5）。
- `CharacterConfig`：+`MaxHP`、`InvincibilityTime`、`HurtStunTime`，嵌入可空 `[Export] DashConfig Dash` / `[Export] AttackConfig Attack`（null=无此能力）。
- project.godot：+`dash`(Shift/X)、`attack`(J/鼠标左键) 动作；+物理层命名（3=玩家判定, 4=敌人判定）。

## 第 2 步：逻辑层状态机（核心）
- `CharacterVisualState` 枚举（idle/run/jump/fall/dash/attack/hurt/dead）替代原 `CharacterState` 枚举（删除）。
- `States/CharacterState.cs` 抽象基类：`Enter/Exit/Process(intent,delta,gravity)/VisualState/OnLanded`，持有 Motor 引用，共享重力/MoveTowards 原语。
- `CharacterMotor` 改为状态机宿主：持有全部状态单例与上下文（速度、朝向、计时器、配置、地面事实），`Process`/`PostPhysics` 对外签名不变、内部委托当前状态；新增 `TryStartDash()/TryStartAttack()`（校验配置+冷却，由 Grounded/Airborne 调用）、`ForceHurt(DamageInfo)`、`Kill()`、`Reset()`、事件 `AttackStarted/AttackActiveChanged`。
- 六个状态类：
  - **Grounded**：地面移动/跳跃（手感三件套入口）；路由冲刺/攻击输入；离地自动转 Airborne。
  - **Airborne**：重力+空中操控+跳跃剪裁；土狼跳；落地转 Grounded；路由冲刺/攻击。
  - **Dash**：Enter 锁方向与速度、关重力；期间忽略跳跃/攻击输入（互斥规则①）；计时结束按地面事实回 Grounded/Airborne，速度×0.4 衔接。
  - **Attack**：前摇→激活(发 AttackActiveChanged)→后摇；地面锁速、空中保惯性；期间忽略冲刺/跳跃（互斥规则②）；结束回 Grounded/Airborne；冷却在 Enter 时启动。
  - **Hurt**：Enter 写入击退速度；硬直期忽略一切输入；结束回 Grounded/Airborne。
  - **Dead**：终态，仅重力+摩擦；由玩家 Reset 解除。
- 互斥是结构性保证：只有 Grounded/Airborne 路由冲刺/攻击意图，Dash/Attack 状态根本不读这些意图。

## 第 3 步：Combat 子系统
- `DamageInfo`（readonly struct：伤害、水平/垂直击退、来源方向 ±1）。
- `Health`（纯 C#）：HP、`TryApplyDamage`（无敌帧内拒绝）、`UpdateTimers`、`RestoreFull`、事件 `Damaged/Died`。
- `Hitbox : Area2D`：`SetActive(bool)` 开关判定；`BeginSwing()` 清空本swing已命中集合；`area_entered` → Hurtbox（同目标只结算一次）；自带激活时可见的调试色块。
- `Hurtbox : Area2D`：`ReceiveHit(info)` 转发给所属 Character。
- 分层：玩家 hurtbox layer3、敌人 hurtbox layer4；玩家 hitbox mask4、敌人 hitbox mask3；hitbox/hurtbox 互相不与实体层碰撞。

## 第 4 步：编排者与表现层接线
- `Character`：发现并订阅 Hitbox/Hurtbox；`AttackActiveChanged→hitbox.SetActive`、`AttackStarted→hitbox.BeginSwing`；Hurtbox 命中→`Health.TryApplyDamage` 成功→`Motor.ForceHurt`；`Health.Died`→`Motor.Kill`，玩家 1s 后回出生点+回满 HP+`Motor.Reset`，敌人 1s 后 `QueueFree`。
- 新增 `Pivot`（Node2D）承载 Sprite+Hitbox+Hurtbox，朝向翻转改为翻 Pivot（Hitbox 随朝向移动），Presenter 的精灵/粒子发现改为深度查找。
- `CharacterPresenter`：新动画映射（dash/attack/hurt/dead）；Bind 增加 Health 参数，无敌帧闪烁（alpha 抖动）。

## 第 5 步：AI 升级（输入层内部小状态机）
`SlimeAIInputSource`：+`ChaseDetector`(Area2D, mask=玩家实体层, 半径90) 与 `AttackDistance`(26)。三层行为：
- Patrol：现有墙/崖逻辑不变。
- Chase：探测到玩家 → 朝玩家移动；遇宽沟停下（MoveAxis=0）不再调头；遇墙跳。
- Attack：水平距离≤AttackDistance 且冷却好 → `AttackPressed` 脉冲。
玩家脱离视野回 Patrol。意图结构与玩家完全一致。

- `Player.tscn`/`Slime.tscn`：分层设置；`Slime.tscn` +ChaseDetector。
- `player_config.tres`：HP5+冲刺+攻击；`slime_config.tres`：HP2+攻击(伤1)+无冲刺。
- 扩展 `generate_placeholder_art.py`：玩家与史莱姆各 +dash/attack/hurt/death 帧；frames.tres 注册新动画。

## 第 7 步：程序化验证（headless 探针，验证后移除）
临时 TestProbe 用 `Input.ActionPress/ActionRelease` 脚本化输入，逐项输出 PASS/FAIL：
1. 冲刺中按攻击 → 仍处 Dash（互斥①）
2. 攻击中按冲刺 → 仍处 Attack（互斥②）
3. 攻击中按跳 → 不起跳
4. 攻击激活期命中 → 对方 HP 下降+进 Hurt+击退
5. 无敌帧内再受击 → HP 不变
6. HP 归零 → Dead；敌人节点被释放
7. 玩家靠近史莱姆 → Chase（x 逼近）；进入攻击距离 → 史莱姆出攻击
8. 回归：玩家远离时巡逻行为不变
通过后删除探针、重建、最终 headless 零错误确认。

## 验收标准
- 编译零错误、运行零报错；上述 8 项探针断言全 PASS。
- 试玩：Shift 冲刺、J 攻击有前摇/判定/后摇节奏；被史莱姆打会硬直击退、HP 扣减、死亡重生；史莱姆会追人、打人、被打死。
- 互斥规则成立且由状态机结构保证，而非散落的 if。
